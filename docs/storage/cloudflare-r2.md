# Каталоговые медиа в Cloudflare R2

## Настройка владельцем

1. В Cloudflare откройте R2 и проверьте, что сервис уже включён. Подключение платежей, checkout и принятие платных условий выполняет только владелец.
2. Выберите отдельный **закрытый** бакет для Danceflow. Не включайте публичный `r2.dev` или публичный домен: медиа выдаёт API с allowlist. В подключённом аккаунте найден `danceflow-media`; новые бакеты не создавались.
3. Создайте R2 S3 API token с **Object Read & Write**, ограниченный только этим бакетом. Не используйте глобальный токен Cloudflare или ключи с административными правами. Интеграция Cloudflare позволяет проверить аккаунт/бакет, но не заменяет S3 credentials приложения.
4. Добавьте `CLOUDFLARE_R2_ACCESS_KEY_ID` и `CLOUDFLARE_R2_SECRET_ACCESS_KEY` исключительно в Replit Secrets. Не вставляйте значения в чат, клиентский код, Git, команды curl или журналы.
5. Установите серверные переменные `CLOUDFLARE_R2_ACCOUNT_ID` (32-символьный account ID) и `CLOUDFLARE_R2_BUCKET_NAME` (имя бакета). Имена настроек одинаковы в разработке и целевой среде. Ключи должны быть доступны серверу в нужной среде; префиксы `VITE_` / `EXPO_PUBLIC_` недопустимы.
6. Перезапустите API workflow. Используется только стандартный endpoint `https://<account-id>.r2.cloudflarestorage.com`, регион `auto`. Произвольный S3 endpoint не принимается.

Отсутствующая или некорректная конфигурация возвращает HTTP 503 с `code: r2_not_configured`, без значений настроек. Ошибки доступа R2 возвращают безопасное сообщение 503. Несуществующий разрешённый объект — 404. Автоматического отката к импортированному App Storage нет.

## Файлы и восстановление

Бакет содержит объекты `dance-templates/<id>/<asset>`. Разрешены только:

- ID: `trend-01`, `trend-02`, `trend-03`, `trend-04`, `trend-05`, `trend-06`.
- Файлы: `video.mp4`, `preview.mp4`, `preview.webm`, `poster.jpg`, `character-01.jpg`, `character-02.jpg`, `reference-poster.jpg`, `result.mp4`, `result-preview.mp4`, `result.webm`.

API не предоставляет list/delete, произвольные ключи, выбор бакета или подписанные S3 URL. Ограничение токена бакетом защищает остальные бакеты; фиксированный префикс и allowlist дополнительно ограничивают сервер.

Исходный ZIP не содержит каталоговые ролики и постеры. Для восстановления нужны оригиналы от владельца или законный доступ к исходному хранилищу. Нельзя считать перенос кода переносом файлов. Загрузите каждый предоставленный файл по соответствующему ID/имени; проверьте воспроизведение. MP4-оригиналы остаются входами генерации; WebM — отдельные браузерные превью, а не замена оригинала. Проверка сигнатуры не гарантирует декодируемость: подготовьте и проверьте ролики заранее.

## Серверный путь будущей админки

`PUT /api/admin/dance-templates/:id/:asset` принимает исходные байты (не JSON, base64 или multipart).

- Проверяется действующая серверная сессия Better Auth, её привязка к внутреннему аккаунту, роль администратора и отсутствие блокировки.
- Cookie-запрос требует корректный `Origin`, как остальные операции админки. Нативный клиент без Origin должен передать проверяемый Bearer token.
- `Content-Type` строго соответствует имени: `video/mp4`, `video/webm`, `image/jpeg`. Сжатые тела запрещены.
- Максимум: видео 100 MiB, JPEG 10 MiB. Проверяются непустое тело и сигнатура MP4/WebM/JPEG; это не антивирусная проверка и не перекодирование.
- Одновременно сервер принимает одну загрузку; вторая получает 429 и `Retry-After: 5`. Прерванные загрузки не записываются; слот сохраняется до завершения уже начатой записи R2.
- Один PUT атомарно создаёт или заменяет файл. Существующий файл сохраняется до успешной записи. Последняя успешная запись выигрывает; для нескольких реплик глобальная очередь/защита от параллельного редактирования не реализована.
- Ответ 200: `{ id, asset, size, etag }`. Журнал аудита содержит администратора, разрешённый ID/имя и число байт, но не ключи или тело файла.
- При 503 после PUT результат мог сохраниться (например, если не записался аудит). Проверьте публичный файл перед повтором.

UI управления каталогом пока не входит в эту работу. Не передавайте S3-ключи будущей админке: она должна использовать этот маршрут с обычной сессией пользователя.

В сгенерированном клиенте `putCatalogueMedia` тип тела — `Blob`; заголовок по умолчанию `video/mp4`. Для WebM/JPEG обязательно переопределяйте `Content-Type` в параметрах запроса. Общая библиотека Zod использует DOM-типы для этого переносимого бинарного контракта, а не Node-only `Buffer`.

## Публичная выдача и обновления

`GET` / `HEAD /api/dance-templates/:id/:asset`: корректный MIME, `nosniff`, `Accept-Ranges: bytes`, полный ответ 200, один диапазон/суффикс 206, некорректный диапазон 416 с размером. Мультидиапазоны не поддерживаются. `If-Range` учитывает ETag/дату.

`ETag`, `Last-Modified`, `Cache-Control: public, max-age=0, must-revalidate` позволяют хранить байты у клиента, но требуют перепроверки перед повторным использованием. Условный GET возвращает 304. Серверного дискового кэша нет: замена через API или Cloudflare dashboard видна следующему запросу. Уже загруженные/проигрываемые байты не изменятся до следующего запроса. `If-Match` между HEAD и GET не даёт смешать метаданные и содержимое разных версий.

## Проверки

- `pnpm --filter @workspace/api-server test` — изолированные offline-тесты, синтетические S3 credentials, без расходов Higgsfield и без реального R2.
- `pnpm run typecheck` — проверка типов всего workspace.
- Для реального smoke-теста нужен работающий API, `ffmpeg`, R2 Secrets и **свободный** слот `dance-templates/trend-06/result-preview.mp4`:

  ```sh
  pnpm --filter @workspace/api-server exec tsx scripts/verify-r2.ts "https://$REPLIT_DEV_DOMAIN/api" --temporary-upload
  ```

  Скрипт создаёт секундный технический ролик, проверяет загрузку, замену, GET, HEAD, 206, ETag, отмену/параллельные запросы и удаляет **только созданный им объект** с проверкой ETag. Непустой слот не перезаписывает. Не запускайте параллельно с восстановлением/редактированием этого слота. Операции R2 могут тарифицироваться по условиям владельца; Higgsfield не вызывается. При прерывании процесса проверьте слот и вручную удалите только технический ролик, если он остался.

Smoke-тест не является восстановлением каталога. После его очистки отсутствующие оригиналы по-прежнему возвращают 404.
