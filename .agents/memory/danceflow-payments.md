Для Android-версии в RuStore пользователь уточнил: «там в рустор надо их подписку подключать».
Для этого канала ориентироваться на подписки RuStore, а не на прежний план ЮKassa.
Пользователь подтвердил: приложение в RuStore Console создано, монетизация подключена.
Ранее пользователь выбрал «Веб и Android, Россия» и «Автоматические списания»
через ЮKassa; для веба этот выбор не отменён. iOS не входит в выбранный этап.

**Why:** Пользователь скорректировал способ оплаты для RuStore после предложения
подключить ЮKassa; ранее отверг RevenueCat. Готовность кабинета подтвердил сам пользователь.

**How to apply:** Различать каналы RuStore и веб, не предлагать ЮKassa вместо
подписок RuStore в Android-релизе этого магазина. Не считать слова пользователя
подтверждением универсальной обязательности RuStore Billing: требования проверять
по официальным документам. Выбор направления не означает разрешения включить
реальные списания без готовности продавца и проверки оплаты.

Подписка должна восстанавливаться на новом телефоне через тот же аккаунт.
Локальный выбор тарифа не является покупкой и не должен давать платный доступ.

**Why:** До реальных продаж пользователь потребовал привязать будущие покупки
к стабильному аккаунту и исключить показ чужой подписки при смене аккаунта.

**How to apply:** При подключении оплаты связывать покупку с подтверждённым
сервером аккаунтом, не с устройством, локальным состоянием или введённой почтой.
Не переносить подписку между разными аккаунтами автоматически.

Выбор тарифов показывать поверх текущего экрана: снизу на телефоне,
по центру на компьютере, с прямой ссылкой. Управление действующей подпиской
оставлять в аккаунте.

**Why:** Пользователь согласовал такой вариант для прода, чтобы просмотр тарифов
не прерывал создание танца и не сбрасывал заполненную форму.

**How to apply:** При подключении оплаты сохранять этот сценарий открытия
и возврата; не переносить управление и отмену подписки в окно выбора тарифов.
