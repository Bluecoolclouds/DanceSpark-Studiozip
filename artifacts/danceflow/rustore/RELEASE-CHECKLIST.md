# Danceflow: подготовка без публикации

**Релиз НЕ готов к отправке. Ничего не публиковать в Replit и RuStore без отдельного разрешения владельца.**

## Что подготовлено технически

- Постоянный Android package: `ru.danceflow.app`, первая версия `1.0.0`, `versionCode: 1`. При обновлениях повышать versionCode и сохранять пакет и сертификат.
- `allowBackup: false`: данные аккаунта не должны автоматически восстанавливаться из Android backup.
- Микрофон и геолокация заблокированы в Expo-конфигурации. Камера/выбор медиа/сохранение результата — только для действий пользователя. После native-сборки проверить merged manifest и реальный отказ в разрешениях.
- Native release требует **EXPO_PUBLIC_API_ORIGIN**: абсолютный постоянный HTTPS-origin без `/api`, query, логина и пароля. Путь `/api` добавляет существующий API-клиент. Нет fallback на development-домен. Expo web продолжает использовать same-origin `/api`.
- Проверка конфигурации: `pnpm --filter @workspace/danceflow check:android-release`. Сейчас ожидаемо отказывает: постоянного API и production publishable key Clerk нет. Прохождение этой проверки не доказывает доступность API и корректность подписи.
- «Моё → Удалить аккаунт»: подтверждение `УДАЛИТЬ`, только собственный серверный аккаунт, запрет новых действий, очистка R2/БД/Clerk с повтором при ошибке, локальная очистка с маркером восстановления.
- Последний администратор должен назначить замену. Активные/неопределённые генерации нужно завершить/сверить без нового платного запроса. Связанный Logto не удаляется автоматически и блокирует начало удаления; миграция на него не входит в релиз.
- Технические дневные суммы расходов обезличиваются: нет account/job/provider ID. Это не позволяет удалить аккаунт и обойти дневной бюджет. Агрегаты удаляются спустя 30 дней при включённой плановой очистке.

## Плановая очистка: утверждено, но пока не включено

Исходные видео R2 — 7 дней с загрузки. Завершённые задания и ссылки — 30 дней с завершения. Пока есть активное/неопределённое задание, все исходники этого аккаунта сохраняются. Неопределённые задания не истекают автоматически: их нужно сверить с поставщиком, не повторяя платный запрос.

Серверная настройка **DANCEFLOW_DATA_CLEANUP_ENABLED=true** включает периодический обход пачками: до 25 аккаунтов и 250 истёкших заданий за проход; полный обход повторяется примерно раз в час. Сейчас настройка не включалась, существующие данные не чистились. Не обещать удаление ровно на границе срока.

Перед включением:
1. Проверить резервную копию и доступ к восстановлению БД/R2.
2. На отдельном тестовом аккаунте проверить старые и свежие исходники, завершённое и неопределённое задание.
3. Проверить, что общий каталог и чужие видео не изменились.
4. Включить настройку через защищённые настройки окружения сервера.
5. Проверять категории `source_retention_retry`, `account_deletion_retry`, `account_maintenance_retry` в журналах. В них нет email, исходных URL и данных поставщиков. При ошибке запрос удаления остаётся в БД, а не выдаётся за завершённый.

Не устанавливать bucket-wide lifecycle rule: пользовательские исходники и каталог используют одно хранилище. Не удалять общий bucket.

## Платный запуск и доступ модератора

Направление не менялось: ЮKassa, веб + Android в России, ежемесячное автопродление. Пока оплата отключена, обычному новому пользователю доступ не продаётся, генерация без серверной подписки не разрешается.

После юридического согласования и готовности продавца нужен отдельный этап интеграции: тестовая первая оплата, отдельное согласие на сохранение способа оплаты/автосписания, сумма/период, отмена последующих списаний и дата доступа, восстановление с сервера, webhooks/идемпотентность, сверка, возвраты. При удалении аккаунта сначала прекращать будущие списания — текущую реализацию удаления нельзя выпускать с будущими автосписаниями без этой связи.

Для модерации заранее создать отдельный обычный аккаунт и согласовать ограниченный доступ и небольшой бюджет. Текущая админка меняет блокировку и дневной лимит, но не выдаёт подписку: проверяемый способ выдачи тестового доступа должен быть добавлен на этапе платежей. Пока это блокер подачи. Не выдавать права администратора, не отключать проверку подписки, квоты и бюджет. Передать логин через предусмотренное кабинетом RuStore защищённое поле; не писать пароль в эту папку. Реальные генерации для модератора требуют отдельного разрешения на расходы.
