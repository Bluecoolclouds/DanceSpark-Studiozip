## Что необходимо уточнить в кабинете и с юристом

- Роли оператора/обработчиков, основания обработки, локализацию первичного сбора данных граждан РФ и допустимость трансграничной передачи. Наличие SDK или географической настройки само по себе не подтверждает соблюдение закона.
- Replit: проект ещё не опубликован и регион не выбран. По официальной документации регион публикации выбирается заранее и не меняется после публикации; опубликованные compute/database/Object Storage размещаются в выбранной географии, но ранее созданные development-ресурсы могут находиться в другом месте. Доступного региона РФ в перечне нет. Проверить, где находятся используемая БД и созданные объекты, до публикации. Источники: [geography](https://docs.replit.com/features/publishing/project-geography), [deployments](https://docs.replit.com/learn/projects-and-artifacts/replit-deployments).
- Better Auth работает внутри собственного API и использует его БД, а не отдельный сервис Clerk/Logto. Это не подтверждает российское размещение или соответствие требованиям локализации. Проверить реальную географию и договоры хостинга/БД. Старые записи Clerk/Logto не удаляются автоматически локальным удалением Better Auth: нужен отдельный порядок обращения с историческими данными.
- SMTP пока не подключён: подтверждение email и восстановление пароля по почте недоступны, адреса верифицированными не считаются. При подключении почтового обработчика обновить декларацию и политику.
- Cloudflare R2: код указывает только S3-регион `auto`; фактическое местонахождение/юрисдикция бакета видны в Cloudflare и здесь не подтверждены. Проверить бакет и действующие условия; географический hint нельзя считать подтверждением российского размещения. Источник: [R2 data location](https://developers.cloudflare.com/r2/reference/data-location/).
- Higgsfield: API-документация сообщает срок файлов запроса 7 дней после завершения по умолчанию. После удаления файлов промпт и параметры остаются в записи; отдельный `DELETE /requests/{request_id}` удаляет входы, выходы и параметры завершённого запроса, но оставляет биллинговые записи. Приложение этот API не вызывает, поэтому удаление аккаунта Danceflow не удаляет запросы у поставщика. Проверить условия аккаунта и определить, как реализовать/обслуживать запросы удаления до выпуска. Источники: [retention and deletion](https://docs.higgsfield.ai/docs/enterprise/data-retention), [delete request API](https://docs.higgsfield.ai/docs/api-reference/requests/delete-request-data).
- Точный состав SDK в итоговом native release, их телеметрия, сетевые обращения и пользовательские согласия. Проверка исходников и Expo Go не заменяет эту проверку.
- Реальные правила аналитики каталога. Не объявлять сбор отсутствующим, пока приложение отправляет открытия.
- Платежи сейчас отключены. Для Android-версии в RuStore выбраны подписки RuStore; ЮKassa — отдельный прежний план для веба. Перед включением обновить декларацию по фактическому SDK/API: идентификаторы платежей/подписок, привязка к аккаунту, получатели данных, техническая телеметрия SDK, бухгалтерские сроки, фискализация, отмена и возвраты.

## Удаление и обязательная проверка

Вход → «Моё → Удалить аккаунт» → описание последствий → ввод `УДАЛИТЬ`. Передаётся только подтверждение; идентификатор удаляемого аккаунта определяется из проверенной сессии.

Запрос сначала сохраняется в БД и отключает новые действия. Очистка R2 и БД, включая локального пользователя Better Auth и его сессии/учётные данные, выполняется повторяемо. При ошибке данные/запрос остаются для продолжения, а не выдаются за удалённые. Сервер не подтверждает удаление у Higgsfield или у исторических внешних провайдеров. Локальная очистка касается этого устройства; галерею и другие устройства пользователь очищает самостоятельно.

Плановая очистка по срокам **ещё не включена**. До выпуска проверить резервную копию, контрольный тестовый набор, затем включить серверную настройку и проверить фактическое удаление. Активные/неопределённые задания защищены от удаления до сверки. Исторические внешние аккаунты и не реализованное удаление запросов Higgsfield требуют отдельной процедуры, но прежняя связь Logto больше не блокирует локальное удаление Better Auth. Не объявлять удаление у всех поставщиков автоматическим.
