# Danceflow — пакет подготовки к RuStore

**Обновлено 6 ноября 2026 года. Это черновик, не отправлять на модерацию.**

Публикация API и отправка в магазин требуют отдельных решений владельца. Доступного подтверждённого production URL сейчас нет. SMTP отложен по решению владельца.

## Карточка приложения

**Название:** Danceflow  
**Краткое описание:** Создавай танцевальные видео из фото и собственных исходников.  
**Поддержка:** danceflow@meduha.app

**Полное описание — черновик:**

Danceflow помогает создавать танцевальные видео. Выбери видео из каталога или загрузи собственное, добавь фотографии и настрой параметры генерации.

В приложении доступны «Лёгкий Свапер» и «Свапер», перенос движения и замена объекта. Сохраняй черновики, возвращайся к своим проектам и сохраняй готовые ролики на устройство.

Для генерации нужен аккаунт и доступные кредиты. Работа зависит от доступности внешнего сервиса генерации. Оплата в приложении пока не подключена.

Используй только материалы, на которые у тебя есть права и необходимые согласия изображённых людей.

**Целевая аудитория:** взрослые 18+ по решению владельца. Рейтинг RuStore ещё не утверждён; ограничения генерации и доступ несовершеннолетних остаются в [возрастном чек-листе](AGE-CLASSIFICATION.md).

## Что уже подготовлено

- Постоянный package `ru.danceflow.app`, версия `1.0.0`, versionCode `1`; пакет и сертификат нельзя менять при обновлении.
- Вход через собственный Better Auth: email/пароль, сессии в БД, локальное удаление учётных данных. Clerk/Logto больше не используются для текущего входа. Старые внешние аккаунты требуют отдельной операторской обработки.
- Почта пока не отправляется: нет подтверждения адреса и восстановления пароля по email. Интерфейс не обещает их доступность. Это ограничение нужно проверить на модераторском сценарии.
- Микрофон, геолокация, фоновые координаты, наложение поверх окон и биометрия явно заблокированы в Expo-конфигурации. Камера, выбор медиа и сохранение видео остаются доступными.
- Подготовлена непрозрачная store-иконка 512×512: `generated-artifacts/rustore/danceflow-store-icon-512.png` от корня проекта. Исходная иконка приложения не менялась.
- Четыре черновых снимка в `screenshots/`, каждый 402×874, укладываются в технические ограничения. Это старые снимки браузерного preview, а не актуальный Android-релиз. На `01-home.jpg` не загрузился постер; этот кадр обязательно заменить.

## Проверки

Из корня проекта:

```sh
pnpm --filter @workspace/danceflow test
pnpm --filter @workspace/danceflow typecheck
pnpm --filter @workspace/danceflow check:rustore-assets
pnpm --filter @workspace/danceflow check:android-release
pnpm --filter @workspace/api-server check:auth-release
pnpm --filter @workspace/api-server check:auth-database
```

Две проверки release-конфигурации должны отказывать, пока не заданы настоящие production origins. Не подставлять preview-домен или произвольный домен ради зелёного результата. Проверка БД проверяет только БД текущего процесса, не будущую production-базу.

Повторное создание иконки (каталог вывода уже существует после подготовки):

```sh
ffmpeg -y -i artifacts/danceflow/assets/images/icon.png -vf 'scale=512:512,format=rgb24' -frames:v 1 generated-artifacts/rustore/danceflow-store-icon-512.png
```
