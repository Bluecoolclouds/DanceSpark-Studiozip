# Danceflow — инструкция модератору RuStore

**Внутренний черновик. Сейчас не отправлять в комментарии к версии:** production-сборки и проверенной учётной записи модератора ещё нет. Не указывайте в этом файле пароль, код доступа или ключи.

## Что должен получить модератор

- Подписанную тестовую Android-сборку `ru.danceflow.app` с постоянным доступным API и проверенным входом.
- Отдельную обычную тестовую учётную запись без роли администратора; её доступ и небольшой лимит должны быть заранее проверены на именно этой версии.
- Данные входа передавать только через защищённое поле «Комментарии для модератора» в RuStore Console. Не помещать их в Git, описание приложения, чат или README.
- Не запускать запросы, которые могут создать платный расход, пока владелец отдельно не разрешил тестовый бюджет.

## Сценарий проверки после подготовки доступа

1. Установить переданную тестовую версию Danceflow из канала модерации RuStore и войти по отдельным тестовым данным.
2. Открыть вкладку «Танцы», выбрать доступную карточку каталога и проверить её изображение/видеопример.
3. Перейти в «Создать», проверить выбор «Лёгкий Свапер» и «Свапер», затем «Перенос движения» и «Замена объекта».
4. Открыть источник из трендов либо выбрать заранее подготовленные тестовые материалы, на обработку которых есть согласие. Проверить экран параметров и доступные разрешения Android.
5. Если тестовый доступ и бюджет разрешены, запустить одну безопасную тестовую генерацию. Дождаться результата, открыть его и проверить сохранение/системное меню отправки. Не повторять неизвестный или зависший запрос: сначала сверить статус с владельцем.
6. Открыть «Моё», проверить доступные черновики, документы, конфиденциальность и поддержку. Удаление аккаунта проверять только на отдельной одноразовой тестовой учётной записи после согласования: удаление необратимо.
7. Если вход, выдача доступа, источник данных или результат недоступны, сообщить владельцу шаг и текст ошибки. Не использовать личный аккаунт и не менять настройки администратора.

## Текущие ограничения

- Свежей подписанной версии после перехода на Better Auth нет. Историческая сборка до перехода не заменяет новый релиз; физическое устройство не проверено.
- Новому пользователю пока нельзя купить подписку. Есть серверные дневные бесплатные кредиты для зарегистрированных аккаунтов, но их достаточность для конкретной модели и бюджет модераторского теста нужно проверить отдельно. Предложение тарифов не даёт платный доступ.
- Публичный production API и production Better Auth не подготовлены. Вход — email/пароль; внешние Clerk/Logto в текущем runtime не используются.
- Поэтому пока нельзя предоставить настоящие тестовые логин/пароль или обещать проверку генерации. Сначала подготовить сборку и отдельный не-администраторский тестовый доступ; затем заменить этот черновик реальными шагами и передать данные только в RuStore Console.
- SMTP отложен: письма подтверждения и сброса пароля не отправляются. Тестовый вход должен работать без получения письма. Не выдавать модератору доступ к админке.
